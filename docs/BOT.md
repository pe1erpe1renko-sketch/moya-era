# Телеграм-бот: что нужно сделать программистам

Бот живёт внутри этого же репозитория: общая база, общие тексты,
отдельного сервиса нет. **Пока нет токена — бот выключен, и сайт
работает как обычно.** Ничего отключать не нужно.

## Шаги

### 1. Завести бота

1. В телеграме написать [@BotFather](https://t.me/BotFather), команда `/newbot`.
2. Задать имя и адрес (адрес обязан заканчиваться на `bot`, например `moyaera_bot`).
3. BotFather пришлёт **токен** вида `1234567890:AA...` — это `TELEGRAM_BOT_TOKEN`.
4. Там же `/setcommands` и вставить:
   ```
   settings - Что показывать в сводке
   zone - Часовой пояс
   archive - Прошлые сводки
   stop - Отписаться
   ```

### 2. Переменные окружения (Vercel → Settings → Environment Variables)

| Переменная | Что это | Обязательна |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от BotFather | да, иначе бот выключен |
| `TELEGRAM_BOT_NAME` | адрес бота без «@», например `moyaera_bot` | да, из него собираются ссылки привязки |
| `TELEGRAM_WEBHOOK_SECRET` | любая случайная строка, 32+ знака | да, ей подписаны запросы телеграма |
| `CRON_SECRET` | любая случайная строка | да, ей подписаны задачи по расписанию |

Все четыре — **без** префикса `NEXT_PUBLIC_`: они серверные и в браузер попадать не должны.

Случайную строку удобно взять так: `openssl rand -hex 32`.

### 3. Миграция

Выполнить `supabase/migrations/20260906000000_telegram_bot.sql` — появятся
таблицы `bot_links` и `bot_digests`.

### 4. Указать телеграму адрес вебхука

Одной командой, подставив токен, домен и секрет:

```bash
curl -X POST "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://<домен>/api/telegram/webhook",
    "secret_token": "<TELEGRAM_WEBHOOK_SECRET>",
    "allowed_updates": ["message", "callback_query"]
  }'
```

Проверить: `curl "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"` —
в ответе должен быть ваш адрес и `pending_update_count: 0`.

### 5. Задачи по расписанию

Расписание уже лежит в `vercel.json` и подхватится при деплое:

| Задача | Когда | Зачем |
|---|---|---|
| `/api/cron/warm` | 01:00 UTC (04:00 мск) | пишет тексты на день заранее, до рассылки |
| `/api/cron/digest` | каждые 10 минут | шлёт тем, у кого уже наступило 8 утра |

Vercel подписывает вызовы заголовком `Authorization: Bearer $CRON_SECRET`
— переменную нужно завести, иначе проверка пропустит кого угодно.

**Задачи по расписанию доступны на тарифе Pro.** На бесплатном они не
запускаются, и рассылки не будет — вебхук при этом работает.

### 6. Проверить вживую

- Открыть кабинет → «Телеграм-бот» → скопировать ссылку на своего человека.
- Открыть ссылку, нажать «Старт» → должно прийти «Готово…».
- Открыть ту же ссылку со второго аккаунта → должно прийти «уже занята».
- В кабинете отозвать привязку → ссылка перестаёт работать.
- Дёрнуть руками: `curl -H "Authorization: Bearer $CRON_SECRET" https://<домен>/api/cron/digest`
  — в ответе `{"ok":true,"due":N,"sent":N}`.

## Что уже закрыто тестами

Привязка и отказ второму, отзыв, лимиты по тарифу, выбор направлений,
сборка сводки и совпадение её ключей с сайтом, потолок в 22 генерации на
сутки, расчёт времени отправки по поясу (включая пояса со сдвигом на
полчаса), темп отправки, голос реплик.

## Что проверяется только вживую

Доставка сообщения, разметка кнопок в телеграме, приём вебхука с
настоящей подписью, поведение при 429 и при блокировке бота, работа
расписания Vercel.

## Пределы

Телеграм принимает у бота около 30 сообщений в секунду; шлём 25 с
запасом. Один запуск задачи укладывается в 300 секунд — это примерно
7 500 сводок; при большем числе подписчиков очередь разберут следующие
запуски (они идут каждые 10 минут), но за час рассылка обслужит около
90 000 человек. Дальше нужно дробить: несколько задач с разными
диапазонами или очередь.
