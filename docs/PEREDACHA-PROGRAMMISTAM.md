# Моя Эра — передача программистам

**Что это.** Готовый фронтенд и серверная логика сайта на Next.js 16. Код собирается, тесты проходят, интерфейс проверен на десктопе и телефоне. Чтобы сайт заработал на 100 %, нужно подключить четыре внешних сервиса и заполнить переменные окружения. Кода писать не нужно — только настройка.

**Как проверить, что всё сделано:** в конце файла чек-лист приёмки. Пока все пункты не зелёные — не запускаем.

---

## 0. Что где

| | |
|---|---|
| Репозиторий | GitHub, ветка `main`. Деплой — Vercel, автоматически при пуше в `main` |
| Стек | Next.js 16.3 · React 19 · Tailwind 4 · Supabase (Postgres + Auth) · KIE (нейросеть) · ЮKassa |
| Локально | `npm ci` → `cp .env.example .env.local` → `npm run dev` → http://localhost:3000 |
| Тесты | `npm test` — движок матрицы, должен печатать «ВСЕ ТЕСТЫ ПРОЙДЕНЫ» |
| Сборка | `npm run build` — без ошибок |

Без переменных Supabase сайт работает в **демо-режиме**: авторизация и данные живут в браузере, все разборы открыты. Это для просмотра, не для прода. Как только заданы `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`, демо выключается автоматически.

## 1. Переменные окружения

Все — в Vercel → Project → Settings → Environment Variables (Production и Preview). Шаблон — `.env.example`.

| Переменная | Откуда | Где нужна |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | боевой домен, `https://moyaera.ru` | canonical, OG, sitemap |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase → Project Settings → API → Project URL | клиент и сервер |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | там же → `anon` `public` | клиент и сервер |
| `SUPABASE_SERVICE_ROLE_KEY` | там же → `service_role` **secret** | **только сервер**. Никогда не добавлять префикс `NEXT_PUBLIC_` |
| `LLM_API_KEY` | kie.ai → API Key | только сервер |
| `LLM_BASE_URL` | `https://api.kie.ai/claude` (уже в шаблоне) | сервер |
| `LLM_MODEL_TEXTS` | идентификатор модели для текстов разборов (см. п. 3) | сервер |
| `LLM_MODEL_CHAT` | идентификатор модели для чата (см. п. 3) | сервер |
| `NEXT_PUBLIC_METRIKA_ID` | номер счётчика Яндекс.Метрики | клиент |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | кабинет ЮKassa → Интеграция → Ключи API | только сервер |

## 2. Supabase — база и авторизация

1. Создать проект на supabase.com (регион — любой европейский, ближе к аудитории).
2. **SQL Editor → выполнить пять файлов из `supabase/migrations/` строго по порядку имени:**
   - `20260901060456_…sql` — profiles
   - `20260901074002_…sql` — реферальные коды
   - `20260901074031_…sql` — функция подсчёта приглашённых
   - `20260904000000_core_people_plans_credits_texts.sql` — люди, тарифы, подписки, кредиты, тексты, чат
   Альтернатива: `supabase link` + `supabase db push` через CLI.
3. Authentication → Providers → **Email** включить. «Confirm email» — на усмотрение: если включить, после регистрации человек должен перейти по ссылке из письма (интерфейс это показывает).
4. Authentication → URL Configuration → Site URL = боевой домен; Redirect URLs добавить `https://<домен>/**`.
5. Проверить, что после миграции в таблице `plans` три строки (`basic`, `family`, `pro`) и в `credit_packs` три пакета. **Цены и лимиты меняются прямо в этих таблицах** — деплой не нужен.

**Что делает база:** `people` — люди пользователя (единица тарифа), `subscriptions` — подписки, `credits_ledger` — журнал кредитов (баланс = сумма), `matrix_texts` — кэш текстов разборов, `chat_threads`/`chat_messages` — наставник, `readings` — история. Всё под RLS: пользователь видит только своё; подписки, кредиты и сообщения ассистента пишет только сервер сервисным ключом.

## 3. KIE — нейросеть

Через KIE идут два разных вызова: **тексты разборов** (пишутся один раз, живут в базе навсегда — качество важнее цены) и **чат-наставник** (единственный масштабируемый расход — цена важнее).

1. Ключ — kie.ai/api-key.
2. Проверить ключ и идентификаторы моделей:
   ```bash
   LLM_API_KEY=… node scripts/llm-check.mjs
   ```
   Скрипт делает по тестовому запросу на каждую модель. Если KIE отвечает, что модели нет — открыть список моделей в кабинете KIE и поставить верные идентификаторы в `LLM_MODEL_TEXTS` (нужен Claude Opus последней версии) и `LLM_MODEL_CHAT` (Claude Haiku 4.5).
3. **Наполнить базу текстов до запуска.** Иначе первые посетители будут ждать генерацию каждого вопроса по 5–10 секунд.
   ```bash
   node scripts/fill-texts.mjs --dry     # покажет объём: ~3 300 текстов
   node scripts/fill-texts.mjs           # 1–2 часа; можно прервать и запустить снова — продолжит
   ```
   Нужны те же переменные (`NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `LLM_API_KEY`) в `.env.local` или в окружении. Стоимость разово — порядка 30–60 $ по официальным ценам модели.
4. Аркан дня, личный год и подсказки к точкам, которых нет в базе, генерируются лениво по первому запросу — это нормально.

## 4. Vercel — хостинг

1. vercel.com → Add New → Project → Import репозиторий с GitHub. Framework Preset определится сам (Next.js). Build Command и Output — по умолчанию, не менять.
2. Environment Variables — все из п. 1. Серверные ключи (`SUPABASE_SERVICE_ROLE_KEY`, `LLM_API_KEY`, `YOOKASSA_*`) добавить без галочки «Expose to browser» — в Vercel она есть только у переменных с префиксом `NEXT_PUBLIC_`, так что просто не добавлять префикс.
3. Deploy. Дальше каждый пуш в `main` — автоматический деплой; ветки — превью-адреса.
4. Settings → Domains → добавить домен, прописать DNS по инструкции Vercel (A-запись `76.76.21.21` либо CNAME `cname.vercel-dns.com`).
5. После привязки домена обновить `NEXT_PUBLIC_SITE_URL` и сделать Redeploy.

## 5. ЮKassa — оплата (когда юристы отдадут документы)

Без ключей кнопка «Оплатить» показывает «оплата пока недоступна» — это задумано, не баг.

1. Кабинет ЮKassa → Интеграция → Ключи API: `shopId` и секретный ключ → в Vercel.
2. Интеграция → HTTP-уведомления: адрес `https://<домен>/api/payments/webhook`, событие **payment.succeeded**. Сервер не доверяет телу уведомления: перечитывает платёж по API и только тогда включает подписку или начисляет кредиты. Повторные уведомления безопасны.
3. Проверить в тестовом магазине: тариф → оплата тестовой картой → в кабинете появилась подписка и кредиты.
4. **Автопродление не реализовано намеренно** — до появления оферты с условиями автосписания. Способ оплаты при покупке тарифа сохраняется (`save_payment_method: true`). Когда документы будут: сделать cron (Vercel Cron → `/api/billing/renew`), который за сутки до `subscriptions.current_period_end` создаёт платёж по сохранённому `payment_method_id` и продлевает период. Заготовки логики — в `src/server/payments.ts`.

## 6. Яндекс.Метрика

Создать счётчик → номер в `NEXT_PUBLIC_METRIKA_ID`. В счётчике завести цели типа «JavaScript-событие» с идентификаторами: `calc_submit`, `reading_view`, `paywall_open`, `signup`, `login`, `person_add`, `checkout_open`, `checkout_pay`, `chat_message`. События уже отправляются из кода.

## 8. Что не входит в этот этап

Чтобы не искать несуществующее:

- Telegram-бот и вечерняя рассылка аркана на завтра.
- AI-образы (карточки-талисманы) и облачко-подсказка.
- Автопродление подписки (см. п. 5).
- Натальная карта и дизайн человека считаются частично: знак Солнца есть, полный расчёт в работе (очередь 4). Движок эфемерид готов: `src/lib/ephemeris/` на `astronomy-engine` (MIT), сверен с NASA JPL DE421, тесты в `npm test`. Swiss Ephemeris и обёртки над ним не подключать: AGPL.
- Вход через VK/Google, PDF-выгрузка.

## 9. Правила, которые нельзя нарушать

- `src/lib/matrix/matrixEngine.js` и `contentPositions.js` **не редактировать**. Методика расчёта сверена с четырьмя внешними сервисами; тесты `npm test` — контроль.
- Идентификаторы вопросов (`slot.id`) не переименовывать: на них висят тексты в базе.
- Меняете промпты в `prompts.js` — поднимайте `PROMPT_VERSION`, иначе старые и новые тексты смешаются.
- `SUPABASE_SERVICE_ROLE_KEY` и `LLM_API_KEY` не должны попасть в клиентский код или в Git. `.env*` в `.gitignore`.
- Никаких зачёркнутых цен, таймеров, «осталось N мест» и обещаний предсказать будущее — это позиция продукта и условие эквайринга.
